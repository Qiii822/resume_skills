# 字节跳动 AI 产品经理 · 招聘偏好（7 条）

> 目标公司为字节（尤其 AI 产品 / Agent 方向）时，Step 1 拆解 JD、Step 3 重写时查阅本文件。
> 本文件优先级高于 `style-guide.md` 的通用规则。核心：**弱化空泛 AI 名词堆砌，突出底层能力、业务判断力、端到端落地、迭代复盘。**

## 1. 底层素质优先，学习斜率 > 存量经验

- 看重：好奇心、持续学习力、结构化拆解能力、客户同理心、Owner 意识、逆商、长期主义。
- 校招候选人「无历史思维包袱」是优势，不会单纯因缺实习直接筛掉。
- **落法**：不靠堆实习数量撑场；用项目里的「为什么这么做」体现思考，用复盘体现学习斜率。缺少实习时，把「日常洞察 + 动手实践（调研/原型/AI 工具搭建）」写成经历。

## 2. 项目评判：小而深、真懂真痛的端到端实践 > 宏大叙事

- 项目必须包含四要素：**真实问题、动手落地、可量化效果、复盘迭代**。
- 有实习：重点写「思考 → 执行 → 落地」三件事，深挖失败反思；无实习：写洞察与动手实践。
- **落法**：每条经历保证「问题 → 动作 → 量化结果」闭环，并在至少一条里埋一句「从失败/复盘中学到什么」的扣子（见第 5 条）。

## 3. B 端 AI 产品：壁垒是业务判断力，不是模型技术

- 要懂：客户是谁、策略对哪类客户生效、背后的原因、业务出错的代价、资金流向、客户核心诉求。
- B 端 AI Agent 是「对商家经营结果负责的数字员工」，强调稳定、可信、业务兜底机制，不是聊天机器人。
- **落法**：写 AI 项目时，先写「服务谁、解决什么业务问题、出错代价是什么」，再写技术方案；把「抗幻觉 / 确定性优先 / 兜底」翻译成业务可信度，而非纯技术名词。

## 4. 团队价值观：离价值近、反馈快、能积累业务判断力

- 简历要体现「拿到真实业务结果、数据闭环、端到端落地」。
- 区分两种团队：AI Native（无历史包袱、探索性强、失败率高）vs AI+业务（业务抓手明确、快速产出成果）。
- **落法**：突出「真实业务结果 + 数据闭环」，弱化「探索性 demo」；有实习经验时把业务结果放最前。

## 5. 面试隐性考察：简历要留可深挖的「扣子」

- 面试官会在一面留命题，二面考察迭代能力。简历和项目要预留能证明「收到反馈后能复盘迭代」的钩子。
- **落法**：至少一段经历写「v1 怎么做 → 发现问题 → v2 怎么改」的迭代痕迹（例：全 LLM 聚类成本高/幻觉多，改为确定性优先）。这是二面能展开讲的钩子。

## 6. 技术基础：不用写代码，但懂模型边界、成本、评测体系、概率系统设计

- 要求「端到端验证能力」。
- **落法**：写「模型边界判断（何时用/不用 LLM）、成本可观测、评测体系、确定性 vs 概率的取舍」这些产品决策，而不是罗列 FastAPI/Pydantic/SQLAlchemy 等技术栈清单。

## 7. 简历表达：务实、坦诚、开放，区分个人/团队贡献

- 能接受挑战、可据事实修正想法；不夸大成果，区分「我做的」和「团队做的」。
- **落法**：用「独立完成 / 主导 / 参与」如实标注角色；避免「我一个人扛下所有」式的夸大；保留一个「坦诚承认局限」的口子（如小样本评测、合成数据），比吹「90% 准确率」可信得多。
