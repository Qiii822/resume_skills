# JD 关键词提取 · 反模式

> Step 1 拆解 JD 时查阅，避免「过度解读」和「遗漏隐含职责」两类错误。

## 反模式 A：过度解读

1. **把加分项当必须项**
   "有 XX 经验者优先" 是 nice-to-have，不是硬门槛；不要据此判定用户"不合格"或强行要求补齐。

2. **把团队 / 部门整体职责当成个人职责**
   JD 描述的是这个岗位所在团队做的事，未必每一项都落到这个人头上；提取"核心职责"时抓最相关的主线，不要逐条全列。

3. **把行业套话当真实文化信号**
   每份 JD 都写"扁平化管理、氛围好"；只有反复出现、措辞具体的信号（如"从 0 到 1、闭环、owner"）才有文化判断价值。

4. **把"熟悉 / 了解"和"精通 / 掌握"混为一谈**
   熟悉和精通对应的能力要求天差地别；提取时必须保留原措辞强度，供 Step 2 打分时参考。

5. **把模糊词自动映射成具体技能**
   "有相关经验"不等于某个具体技术；不要替 JD 脑补成具体技术栈再拿它去匹配用户。

## 反模式 B：遗漏隐含职责

1. **只抓名词（技术栈），漏掉动词隐含的能力**
   "优化"隐含性能调优与问题定位；"从 0 到 1"隐含项目管理与推进；"主导"隐含 owner 责任。
   这些动词对应的软性能力，常常才是 JD 真正想筛的点。

2. **漏掉软性要求段**
   沟通、协作、抗压、owner、推动力——常被塞在职责描述或"岗位要求"里，而非单独成节；必须扫一遍。

3. **漏掉"隐性必须项"**
   全文都在围绕某能力但未单列：如整段都在讲推荐系统、却没写"机器学习"。这类是隐性硬门槛。

4. **漏掉带人 / 跨部门 / 面试官等职责**
   出现"指导新人、跨团队、参与招聘"通常暗示 senior 定位，会影响语气与篇幅策略。

5. **漏掉重复出现的词**
   在 JD 中出现 ≥2 次的词通常是真正核心，应优先提取；只扫一遍容易漏掉这类加权信号。

## 操作建议

- 关键词提取 = 显式名词（技术栈）+ 职责动词 + 软性要求 + 出现频率加权。
- 区分"必须 / 加分"只看措辞强度，不靠感觉。
- 拆解完列一张「必须项 / 加分项 / 隐含软性要求」三列表，作为 Step 2 打分的对照基准。
